# 收文 · 我的稍后读

一个跑在自己电脑上的公众号文章收藏夹。看到好文章 → 转发进来 → 有空时统一读。
数据全部存在本地，不依赖任何云服务，**零第三方依赖**（只用 Node 内置模块）。

```
微信里多选文章 ──转发──> WeChatBridge ──> 收文监听器 ──> 抓正文入库 ──> 本地网页
```

## 它是什么 / 它不是什么

**是**：一个本地优先的稍后读应用 —— 链接入库、抓正文、重排版、加分类、打标签、写备注、搜索、收藏、回收站。

**不是**：不是一个「微信聊天记录导出工具」。这一点很重要，请读完 [隐私与边界](#隐私与边界) 一节。

- ❌ 不读微信数据库，不解密、不注入、不 hook、不修改微信进程
- ❌ 不导出聊天记录，不碰你的消息
- ✅ 只用微信**自己导出**的内容（转发出来的明文 ZIP），加上你手动粘贴的链接

## 功能

| 能力 | 说明 |
|---|---|
| 转发即入库 | 微信里多选文章 → 转发到「微信流」→ 5 秒内自动出现在库里（未读） |
| 抓正文重排 | 自动抓 `#js_content` 正文、图片走本机代理过防盗链、字号行距做过阅读优化 |
| 粘贴 / 剪贴板入库 | 复制一段含链接的文字，双击 `收链接.cmd` 全部收进来 |
| 从导出文件导入 | 把聊天记录 `.html` / `.txt` 拖到页面上，自动抽出所有公众号链接（兼容 GBK） |
| 手动收本地文件 | `POST /api/files` 把本机文件复制进库，PDF 内嵌预览 |
| 整理 | 分类、标签、备注、星标收藏、搜索（标题/公众号/正文/备注）、回收站 |
| 手机上用 | 局域网访问同一个地址即可；PWA 支持「分享 → 收文」直接入库 |
| 去重 | 按规范化 URL 去重（只留 `__biz/mid/idx/sn/chksm`），同一篇文章从任何入口转发都只收一条 |

## 快速开始

### 环境要求

- **Node.js 18+**（推荐 22）。不需要 `npm install`，没有任何依赖。
- Windows（启动脚本是 `.cmd`）。其他系统可以直接跑 `node server.js` + `node wx-watch.cjs`。

### 启动

双击 **`启动收文.cmd`**。它会在后台拉起两个进程，然后自己关掉窗口：

1. 收文网页服务（`server.js`，端口 4321）
2. 转发监听器（`wx-watch.cjs`）

几秒后自动打开 <http://localhost:4321>。

- 已经开着再双击会提示 `Shouwen is already running.`，不会重复起。
- 关闭用 **`停止收文.cmd`**。
- 也可以手动跑：

```bash
node server.js            # 只起服务
node wx-watch.cjs         # 只起监听（需要服务已就绪）
node wx-watch.cjs --once  # 单轮扫描，跑完即退
```

终端会打印局域网地址（如 `http://192.168.x.x:4321`），手机连同一个 Wi-Fi 也能打开。

### 让「转发」生效

转发通道依赖 [WeChatBridge（微信流）](https://github.com/freestylefly/WeChatBridge) —— 它往微信的「转发到其他应用」菜单里加一个分享入口，
把官方「合并转发」出来的 ZIP 写到磁盘。装好之后：

1. 手机 / 电脑微信里长按消息 → **多选**，勾选要收的文章
2. 点「分享」→ **转发到其他应用** → 选「微信流」
3. 在目标面板里选 **发给 WorkBuddy**（或「沉淀到文件夹」）
4. 完事。收文这边 5 秒内自动出现这些文章（未读）

监听器盯着 `%LOCALAPPDATA%\WeChatBridge\Inbox\Ready\`，发现新批次就解包 → 抽链接 → 抓正文 → 入库。
收件箱在别处的话，用环境变量 `READLATER_BRIDGE_INBOX` 指过去。

### 不想装 WeChatBridge？

还有两条不依赖任何第三方工具的路：

- **粘贴**：微信里「⋯ → 复制链接」，打开网页 → 添加文章 → 读剪贴板 / 直接粘贴，支持一次粘一批（一行一条）。
- **拖文件**：微信「合并转发」另存为 `.html`，把文件拖到收文页面任意位置，链接自动全部抽出、去重，确认后导入。

## 目录结构

```text
server.js                  # 零依赖 HTTP 服务 + 静态资源 + REST API
wx-watch.cjs               # 转发收文监听器（盯收件箱，解包、抽链接、入库）
ingest-clip.cjs            # 剪贴板 / 命令行收文
lib/
  ingest-config.js         # 服务端与监听器共用的配置
  store.js                 # 数据读写（JSON 原子写）
  fetcher.js               # 抓文章、清洗正文、图片代理与缓存
  html.js                  # HTML 解析小工具
public/                    # 前端（vanilla JS 单页应用 + Service Worker）
data/                      # 运行数据（已 gitignore）
启动收文.cmd / 停止收文.cmd / 收链接.cmd
ui-test.cjs / import-test.cjs   # 回归测试（用无头 Edge 真实点击）
```

## 数据与备份

- 所有数据在 `data/db.json`，图片缓存在 `data/img/`，手动导入的文件副本在 `data/files/`
- 监听进度在 `data/wx-watch-state.json`（记录处理过哪些转发批次）
- 日志在 `data/wx-watch.log`
- **备份 = 复制整个 `data` 目录**
- 卡片右上角 `✕` 是**永久删除**（不进回收站、不可恢复）；`⋯ → 回收站` 是兜底入口

## 配置

复制 `ingest.config.example.json` 为 `ingest.config.json` 后按需修改（该文件已 gitignore，不会污染仓库）。
不创建也能跑，用的是 `lib/ingest-config.js` 里的默认值。

| 键 | 默认 | 说明 |
|---|---|---|
| `serverBase` | `http://127.0.0.1:4321` | 收文服务地址 |
| `intervalMs` | `5000` | 扫描收件箱的间隔（毫秒） |
| `category` | `inbox` | 新条目默认分类 |
| `sourceLabel` | `本地导入` | 手动导入文件时显示的来源名 |
| `exts` | 见文件 | `POST /api/files` 接受的文件扩展名 |
| `maxFileMB` | `200` | 单文件大小上限 |
| `fetchThrottleMs` | `350` | 抓正文时每篇之间的间隔。**别调太小**，突发抓取会被腾讯风控拦成验证码页 |
| `retryCooldownMs` | `8000` | 命中风控后的冷却时间，之后逐条重抓一次 |
| `retryThrottleMs` | `900` | 重抓时每篇之间的间隔 |

环境变量：`PORT`（改端口）、`READLATER_SERVER_BASE`、`READLATER_BRIDGE_INBOX`、
`READLATER_WATCH_STATE` / `READLATER_WATCH_LOG` / `READLATER_WATCH_LOCK`。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/articles` | 列表（支持筛选、搜索） |
| `POST` | `/api/articles` | 按链接入库（自动抓正文） |
| `GET/PATCH/DELETE` | `/api/articles/:id` | 详情 / 更新 / 删除（`?mode=purge` 为永久删除） |
| `POST` | `/api/ingest-text` | 提交一段文本，抽出里面所有公众号链接批量入库 |
| `POST` | `/api/files` | 把本机文件收进库 |
| `GET` | `/api/files/:id` | 预览 / 下载文件副本 |
| `GET` | `/api/stats` | 总数、未读、回收站等统计 |
| `GET` | `/api/img` | 图片代理（带微信防盗链 Referer，白名单 `*.qpic.cn` / `*.qlogo.cn`，磁盘缓存） |

## 隐私与边界

这一节是这个项目存在的前提，请认真看：

1. **不碰微信的数据。** 本项目的自动来源**只有一条**：读 WeChatBridge 写出的转发收件箱目录。
   那是微信**自己导出**的明文文件。项目不读、不解密、不尝试解密微信的任何数据库，
   也不注入或修改微信进程。
2. **不做「聊天记录导出」。** 微信的聊天记录是加密存储的，本项目既不解析它、也不提供这类功能。
   想归档聊天记录请用微信官方的「聊天记录迁移与备份」。
3. **正文与图片的版权属于原作者 / 对应公众号**，不属于本项目、也不属于腾讯。
   抓取正文是为了**你本人离线阅读**；请不要把抓下来的内容再分发、公开发布或用于商业用途。
4. **你的阅读列表在本地。** 只有 `data/` 目录，没有账号、没有上传、没有遥测。
   想分享给别人就复制整个 `data` 目录 —— 但那里面是你的私人阅读记录，注意别误传。
5. **抓取频率已刻意压低**（每篇间隔 350ms，命中风控后冷却 8 秒再重试一次），
   请不要再调快。抓取行为应遵守目标站点的规则。

## 已知限制

- **个别链接抓不到正文**：不带 `chksm` 的裸长链（`/s?__biz=…&mid=…&idx=…&sn=…`）
  会被腾讯风控跳转验证码页，重试也没用；这类条目仍会入库（带标题、公众号），点开可看原文。
  带 `chksm` 的长链则稳定能拿到全文。
- **「分享卡片」型内容**（`item_show_type=8`）微信侧本来就没有网页正文，只会存标题/封面/摘要。
- 监听器是**轮询**的（默认 5 秒），不是实时推送。
- 启动脚本目前只针对 Windows 写了便利封装；macOS / Linux 直接跑两条 `node` 命令即可。
